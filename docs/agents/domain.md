# 领域文档

工程 skills 在探索本仓库时如何消费领域文档。

## 探索前先读

- 仓库根目录的 **`CONTEXT.md`**
- **`docs/adr/`** — 阅读与当前工作区域相关的 ADR

如果这些文件不存在，**静默继续**。不要提示缺失，也不要主动建议创建 ——
`/domain-modeling`（经 `/grill-with-docs` 和 `/improve-codebase-architecture`
触达）会在术语或决策真正落定时惰性创建它们。

## 文件结构

单上下文仓库（本仓库）：

```
/
├── CONTEXT.md
├── docs/adr/
└── src/
```

## 使用词汇表的用词

输出中涉及领域概念时（issue 标题、重构提案、假设、测试名），使用
`CONTEXT.md` 定义的术语，不要漂移到词汇表刻意避开的同义词。

需要的概念不在词汇表里时，这本身是个信号 —— 要么你在发明项目不用的语言
（重新考虑），要么存在真实缺口（记下来交给 `/domain-modeling`）。

## 显式指出 ADR 冲突

输出与既有 ADR 矛盾时，显式指出而非静默覆盖：

> _与 ADR-0007（事件溯源订单）矛盾 —— 但值得重新讨论，因为……_
